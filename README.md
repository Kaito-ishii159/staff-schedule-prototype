# 訪問予定管理 Prototype

社内向け訪問予定管理iPhoneアプリのフェーズ1操作プロトタイプです。架空データのみを使用し、認証・GPS・ルート計算・通知・保存は完成イメージを示すデモとして実装しています。

## 起動

```bash
npm install
npm run dev
```

Node.js 22.20以降を使用してください。React / TypeScript / Vite / Lucideで構成しています。

```bash
npm run build
npm run typecheck
npm run lint
npm test
```

`npm run build` で `dist/` に静的ファイルを生成します。画面遷移はReact内で管理し、相対アセットパスを使用するためGitHub Pagesのサブディレクトリでも動作します。再読み込みするとログイン画面に戻り、予定・新規依頼などのデモ登録データは初期化されます。テーマ・個人用フリーメモ・書類完了チェックは職員単位で端末内に保存します。実際の認証・アクセス制限ではないため、実情報は入力しないでください。

## 主な操作

- デモログイン（職員A）、下部タブ、通知既読化、設定、ログアウト
- 7事業所・70名のダミー職員。予定表は横軸が時間、縦軸が職員。固定名列・固定時間ヘッダー、事業所切替・職員検索に対応
- 予定の追加・詳細・編集・削除。カードを600ms長押し、または「…」から同一事業所の担当＋開始／終了時刻を同時変更。スクロール時は長押しをキャンセル
- 重なる予定は別レーン。変更後は対象職員・時刻に自動スクロール
- 予定種別は定期訪問（青）／担当者会議（紫）／退院前カンファ（緑）／緊急訪問（赤）／契約（黄土）。色と種別名の両方で区別し、内容は自由入力
- 毎週・曜日複数選択・任意終了日。「この予定のみ変更」は `exceptions[元の日付].override`、「今後の予定も変更」はその日を境にシリーズを分割。将来分の個別変更はリセットすることを画面内に明記
- 繰り返し予定の削除は選択した回のみ。日付を移した例外も元の回に紐付け、他の日へ波及しない
- 顧客電話番号を予定登録・編集・詳細に追加。架空番号 `000-0000-0000` を使い、発信ボタンは `tel:` リンク（未登録時は非表示）
- 確認ダイアログから予定をキャンセル。`status: active | cancelled` として削除と区別し、予定表には種別色を残した斜線・薄い文字・キャンセルラベルで表示
- 繰り返しのキャンセルは特定回の `exceptions[元の日付].override.status` に保存。次回は維持し、その後の将来分編集でもキャンセル記録を保持。削除用の例外は `deleted` で区別
- 設定の管理メニューから「キャンセル一覧」へ。予定日の月・担当職員の事業所で絞り込み、件数と日付・時間・訪問先・担当・種別・事業所を表示。詳細から戻ってもフィルターを保持
- 今月のキャンセル例は新宿4件・池袋2件・渋谷2件、前月は新宿・池袋各1件（月末起動時は翌日のカレンダー用1件が翌月になります）。キャンセル済み予定はルート・距離・次の登録予定から除外し、詳細は元の情報を保持するため編集不可
- 自分の訪問先：当日を初期表示し日付切替可能。番号付きピン・時刻順ルート・一覧・区間距離・合計移動時間
- 職員位置：自分以外の最終取得位置・絶対更新日時・次の登録予定。デモ基準日時は当日09:50。位置未取得は明示し、勤務・移動・訪問状態は推測しない
- 両マップは共通SVG地図を利用。道路、交差点、建物、公園、駅、川、現在地を表現。全て架空の位置・距離・所要時間
- 職員追加・事業所追加はReact状態に登録。重複メール・重複事業所名を検証
- 白熊／アニマル／宇宙／南国／花・海・空の5テーマ。オリジナルSVGとCSSを使用し、職員ID単位のlocalStorageキーで端末内保存。参考画像・画像内の個人情報は同梱していません

## work環境・フェーズ1追加機能

- ホームに本日の自分の予定を時刻順で表示。キャンセル・未完了メモも表示し、カードから詳細へ。8つのアイコンタイルから主要機能へアクセス
- 予定詳細の利用者名から月間カレンダーへ。安定した `clientId` で既存予定を集計し、月〜日・複数訪問・時刻・キャンセルを表示。看護○赤／リハビリ●青／モニタリング●緑／キャンセル－を凡例と文字で区別。訪問区分は従来の予定種別5種類とは別項目
- 予定表は「詳細表示／全体表示」の2択。詳細表示は読みやすいカードと横スクロール、全体表示は固定職員列を除いた画面幅へ8〜18時（時間外予定があれば範囲拡張）の時間軸を圧縮。カードは開始時刻・名前・未完了メモの印・キャンセルに簡略化し行高さも圧縮。両モードで固定職員列・時間ヘッダー・種別色・タップ・長押しを維持し、重なるカードは別レーン
- メモは `memoScope: single | recurring`。今回のみのメモは元の発生日に紐付け、日付移動時も維持。`memoCompletions[元の発生日]` で各回の完了を記録し、未完了の「！」から詳細へ。今日完了しても次回の繰り返しメモは残る。編集の「今回のみ／今後」範囲は従来通り
- 書類更新管理は自分の担当利用者のみ。報告書は対象月を切替、計画書はダミーの `nextDueMonth` を表示し、職員・利用者・書類・月ごとのチェックを保存。3か月周期の起点や完了後の自動繰越は未確定のため実装せず、新規利用者の更新月は未設定と表示
- フリーメモは自分用の保存・編集・削除確認に対応。職員別localStorageに保存
- 週間予定は既存予定を月〜日で展開。全職員・検索・前週／次週・今週、横スクロールと固定職員列／曜日ヘッダーに対応。PCは表示幅を拡大
- 利用者管理は設定→管理から。ID（変更不可）・氏名・フリガナ・電話番号・住所・所属事業所・利用状態を保持し、検索／登録／編集／停止・再開／詳細に対応。詳細から月間予定・当該利用者の書類へ移動可能。計画書の次回月も任意に登録できる
- 予定登録・編集は、利用者の氏名・フリガナ・IDによる検索選択を使用。新しい利用者は入力途中に登録でき、予定入力内容を維持して選択へ戻る。住所・電話はマスタ参照専用（変更は利用者管理から）。利用停止は新規候補から外し、既存予定の確認・編集・履歴は維持。新規依頼は下記の新規登録のみのモードを使用
- 予定・月間予定・書類・予定メモ・キャンセル・新規依頼はclientIdで関連付け。マスタ変更は通常予定と例外／キャンセルの表示にも反映。新規依頼の利用者名もIDから解決し、同名の利用者を自動統合しない。利用者・予定・依頼はReact stateのみでリロード時に初期化
- 新規依頼管理は新しい利用者の登録・依頼元・利用者情報・フリー記載を入力し一覧へ追加。既存利用者候補は非表示。承認や推測したステータスは追加しない

## work追加要件（2026-10-18）

- 利用者／職員／事業所／車両は未使用のみ確認後に削除。通常・例外予定、キャンセル、書類、依頼、メモ、車両・アルコール履歴等の関連があればブロック。停止／無効化も維持
- 日別／週間予定に利用者名・フリガナ・ID検索。ClientのID集合で絞り、職員検索とAND。検索クリアあり
- フリーメモは個人／事業所共有タブ。共有は作成者と作成／更新日時付き、officeId別に端末保存（他端末同期は未実装）
- 設定→車両管理で架空車両の登録／編集／停止／削除／履歴。予定は自家用車／社用車を選び、社用車は所属車両必須。履歴は予定由来のデモで、変更／削除前の車両情報も保持
- 設定→移動集計で月・事業所・職員別の累積距離／時間、平均、車種内訳、移動予定日数。平均は暫定的に移動予定のある日の平均。地図と共通の固定デモ区間値で帰着区間は未算入
- マップに選択日と選択月平均の距離・時間、平均比。距離の適否は判定せず、顧客提供の「移動時間の目安（参考）」を表示
- 設定→アルコールチェック。車両／運転手／確認者・出退勤の酒気帯び・体温・指示事項・特記事項を手入力。月／事業所／車両／運転手で絞り詳細へ。詳細の「編集」から共通フォームで修正し、同じIDの記録を更新（件数維持）。設定済みの停止済み車両・職員は既存値だけ選択可能。保存後に更新済み詳細を再表示。自動の運転可否判定・法令準拠保証はなし
- 職員管理→勤務設定で曜日／個別日例外。予定表の両モードに薄い勤務外背景斜線。勤務外でも予定登録は可能
- 予定表内で15%以上のpinch-in→全体、pinch-out→詳細。1ジェスチャー最大1回。ボタン・1本指スクロール・タップ・長押しを維持し、%倍率は追加しない
- 車両・アルコール・勤務設定・マスタ・予定・依頼はReact stateでリロード初期化。テーマ・個人／共有メモ・書類チェックはLocalStorage。実データは入力しないでください

## 追加指摘対応（2026-10-19）

- 週間予定に詳細／全体の2ボタンを追加。全体は列幅・余白・カード・文字量を圧縮し、時刻・利用者・キャンセル・メモ警告を保持。検索・タップ・固定列／ヘッダー・横スクロールを両モードで維持。週間ピンチは追加せず、日別ピンチは従来どおり
- 新規依頼の編集／確認付き削除。登録と共通フォームを使い、編集ではid・requesterStaffId・requesterOfficeIdと件数を維持
- ホームの本日の予定より前に、自分の本日アルコールチェックを全件表示。未登録／チェック済みと車両・出退勤結果・体温・入力された運転可否を確認。管理と共通の登録／詳細／編集を利用し、新規の運転手はログイン職員が初期値。管理は日別／月別と既存フィルターを併用。同日複数可・削除なし
- ホーム→担当利用者。自分を初期表示し、担当職員切替でClient.ownerIdを照合（利用停止を含む）。氏名／フリガナ／ID検索・月間予定・電話・基本情報確認
- 職員登録／編集で基本勤務時間を保存。曜日入力を既存勤務設定と共用し、Staffと勤務のstaffIdを一致させる。個別日例外は保持し、勤務外斜線へ即反映。勤務外の予定登録は制限しない
- 移動集計の計算・表示・参考値は変更なし。本番API等の追加なし。未確定の一意制約・アルコール削除／監査方針・全員の受け持ち表・勤務外制限は仕様書に残す

## 追加指摘2点（2026-10-21）

- 新規依頼のみClientPickerの`new-only`モードを使用。既存利用者の検索欄／候補を出さず、新しいClient登録→自動選択→依頼登録。編集では現在の利用者を保持し、確認付き削除も維持。予定登録／編集の既存利用者検索は変更なし
- 担当利用者は自分を初期選択し、職員マスタの職員（事業所名付き）へ切替可能。`ownerId === selectedStaffId`の中で検索。他職員でも利用停止・月間予定・電話・情報確認を維持。巨大な受け持ち表や本番権限制御は追加しない
- 他職員閲覧の本番権限・事業所範囲と、新規依頼段階でClientへ登録するかは未確定。その他の機能は変更しない

## 検証

`npm test` は35件のドメインテストと55件の画面操作テストを実行します。新規依頼の既存候補非表示・新規利用者登録・編集時の関連維持・確認付き削除、予定登録／編集の氏名・フリガナ・ID検索、担当職員ID切替・担当内検索・他職員の月間予定導線を検証。従来の繰り返し・例外・キャンセル・利用者ID連携・メモ完了・地図・テーマ等の回帰に加え、未使用マスタ削除／関連ありブロック、日別・週間の利用者検索、共有メモ、車両・移動手段・利用履歴、移動集計、アルコール登録／編集／絞り込み（ID・件数維持、他記録不変、停止済み既存値、必須項目）、勤務時間／休日、2段階ピンチの閾値・1ジェスチャー1回・1本指・長押し維持を検証します。

390×844のブラウザ表示でログイン、予定表、当日だけの変更と翌日の維持、2種類の地図、ルート・区間距離、職員／事業所登録、テーマ選択を確認しています。

追加機能も同じスマホ幅で電話ボタン、キャンセル確認・斜線、次回予定の維持、管理一覧の月／事業所切替・詳細遷移を確認しています。検証ブラウザは電話アプリへの外部遷移を禁止するため、iPhone Safariの発信確認画面は未確認です。

## 本番未実装・顧客確認事項

認証、権限制御、DB/API保存、実GPS・バックグラウンド位置共有、Push通知、実地図・経路検索は未実装です。住所・人名・事業所は架空データで、外部への送信はありません。ログインは職員A固定のデモです。
